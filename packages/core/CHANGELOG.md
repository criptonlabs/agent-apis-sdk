# @criptonlabs/agent-apis-core

## 0.1.0

### Minor Changes

- 5b79c01: Concurrent XRPL payments no longer collide. Core: the `X402Payer` port gains an optional `exclusive` section that the paid flow (per-call payments and top-ups) runs signing and the paid retry inside, and a new payment error code `payment-busy` for a payment that could not start. XRPL: payments of one wallet and network are signed one at a time per process, and a payment that waits more than 20 seconds fails with `payment-busy`, unsigned and not charged.

## 0.0.2

### Patch Changes

- 49a2019: Follow API contract 0.27.0. BREAKING (pre-release), response fields follow the API 1:1 with no aliases. XRPL: fee fields are `*_drops`; AMM `trading_fee_pct`; account summary `transfer_fee_pct` replaces `transfer_rate`; trust lines use `peer` and `line_limit`; token `flags` is an object; health uses `ledger_age_seconds` and `load_factor_multiplier`, and `uptime_pct` is a decimal string. Solana: transfer readiness returns `verdict`, `reasons` and `checks_failed` instead of `ready` and `blockers`, with `amount_atomic`; the token verdict is lower case and the raw supply moves to `supply_atomic`; `uptime_pct` is a decimal string. Core: the price index reads `denominations[]`, the prepaid offer has no `activation`, and `meta` may carry a null `ledger_index` or `slot`. Solana transfer preparation raises `transfer-readiness-unknown` when the verdict is `unknown`. New inputs: `domain` (orderbook, slippage), `side` (slippage) and `credentials` (payment readiness, tool and CLI). `depth` accepts the API range, and `quote-dex --depth` text is accepted only as decimal digits, as the API. Asset grammar: 3-character codes are case-sensitive, 40-hex codes are accepted, an MPT id is accepted on payment readiness only, and 4-20 character text codes are refused instead of converted.

## 0.0.1

### Patch Changes

- 489f092: Sync with the released API 0.21.0. BREAKING (pre-release): kit configuration is split into `wallet` (signer, network, asset, URLs), `payment` (the per-call opt-in: `maxPerCall`, `sessionBudget`) and `credits` (`token`, `topupBudget`, and `siwx` on Solana); environment variable names stay. Prepaid credits: spend with a token read from `CRIPTON_CREDITS_TOKEN`, last known balance, idempotency keys, and explicit top-ups with their own `maxAmount` (never `maxPerCall`) and an optional top-up budget; a bought token is shown once and never serialized, logged or handed to a tool result. Solana kit: Sign-In-With-X credit spending and token rotation (`@x402/extensions` as an optional peer). New free price index `prices()`, and API-owned code lists (reasons, warnings, statuses) tolerate unknown values instead of failing with `invalid-response`. New tools `xrpl_credits_status` and `solana_credits_status`, plus the opt-in `solana_credits_topup` (tier `pro`, both purchase caps required, reports `tokenKept`); no purchase tool on XRPL. CLI gains `topup`, `credits`, `rotate-token` (Solana) and per-command `--help`. Dependencies: `@solana/kit` 8.6.0 and `@x402/*` 2.30.0.
- a0bf36b: First version of the SDK: the core package (API client with typed errors, opt-in x402 pay-per-call with spend limits, MCP / AI SDK / Mastra / ElizaOS adapters and CLI runner) and the XRPL kit (typed client for every `/v1/xrpl/*` route, RLUSD x402 payer, payment preparation, DEX quote, 14 tools, ElizaOS plugin, `agent-apis-xrpl` CLI and agent guidance files).
- a2a7421: Hardening from the 2026-10-27 audit: Solana transfer preparation verifies the readiness against the intent (echoed source, destination and mint, SOL decimals, Token or Token-2022 program, raw amount equal to the intent amount) and refuses a mismatch with `invalid-response`; API problems carry their field errors in `details.errors`; the XRPL kit checks account lines (10 to 400) and transactions (1 to 50) limits before the request and advertises them in the tool schemas; the CLI also refuses `--key` and `--payer-key`.
- cca342c: The signed retry waits at least 30 seconds for settlement; when it fails without an answer the amount counts toward the session spend and the client raises `CriptonPaymentError` code `payment-outcome-unknown` instead of a network error, never retrying the payment.
- cca342c: Report the API's prepaid credits answers: a credits-only route raises `CriptonPaymentError` code `credits-required`, and payment and problem errors carry `prepaidOffer` and the problem's `error` member as `reason` (for example on an exhausted daily free quota). The kit still never buys credits.
- a2a7421: New Solana kit `@criptonlabs/agent-apis-solana`: typed client for the `/v1/solana/*` routes, unsigned SOL / SPL (Token and Token-2022) transfer preparation gated by the API's transfer readiness, an opt-in x402 payer in USDC or EURC (fixed asset, official mints, `mainnet` or `devnet`), six tools for MCP, AI SDK, Mastra and ElizaOS, and the `agent-apis-solana` CLI. Core: payers may report a decimal amount (`X402Payer.decimalAmount`) so spend limits and receipts use decimal units when a network offers atomic amounts, and the money module gains `divPow10`.
